Nothing is on the map yet

keeps a ledger — what was decided, deferred, blocked or found across your projects — and puts it in front of the next session without anyone remembering to look. Four things make that work. Each step below does one of them and moves on when it is true.

Not sure yet? Try it with sample data

This builds a complete map from two real public repositories — Tare and Forage — so you can see what Spoke says before you point it at anything of yours. It clones them, scans them, and lays one example of each thing a person records on top: a hold, a block and its chain, a deferral with its ruling, a decision that was superseded, a node gone stale, a former name that still resolves. Every kind of flag the board can raise is raised at least once.

It touches nothing of yours. The store, the project registry and the config all live inside the folder you name below, and the command it gives you back points at them explicitly.

Cloning two repositories takes a few seconds. Needs network access.

    1 Point it at a memory store
    
        
    A memory store is the folder Claude Code keeps a project's memory in —
        ~/.claude/projects/<project>/memory. Spoke reads the records there and
        writes ledger nodes beside them. It never rewrites a record without a ruling.
    
        
    
          What is a memory store, exactly?
          
    It is an ordinary folder of Markdown files kept under git — one file per record,
          with a MEMORY.md index listing them. Claude Code writes them as it
          works; you can read and edit them with anything.
    
          
    Spoke adds a ledger/ directory beside those records and writes its
          own typed nodes there. It commits every write, so the history of what was decided
          is the git history. There is deliberately no default path: a baked-in one
          would silently point a second project at the first project's memories.

      2 Register a project
      
        
      A project is a name and the repos it is made of. Everything else —
        which store, what the products are, what the decisions were — derives from those
        repos, so there is nothing else to fill in.
      
        
      
          What counts as a project?
          
      Whatever you would answer "what are you working on?" with — one product, or a
          whole estate of them. It is a label over a set of repository paths on this machine.
      
          
      Registering several lets one Spoke map each separately, each with its own store
          and its own capability axes. If you are trying Spoke out, one is plenty.

      3 Put something on the map
      
        
      Two ways in. Scan reads the repos and derives the
        products, decisions and shared code they contain — through the same gate a person
        meets, and it reports what it could not read. Or report a problem
        from any page; that becomes an open item the next session is handed.

      4 Declare the capability axes
      
        
      The scale scores products on axes you name — there is
        deliberately no built-in list. Until one exists the scale page says so and shows
        nothing else.
      
        
      
          Declare them on the settings screen
        
      
        
      
        
      Or from a terminal: spoke projects axes --set 'reliability=Reliability:30'.
        This page notices either way.
